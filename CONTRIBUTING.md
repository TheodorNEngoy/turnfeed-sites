# Contributing

Start with the [local setup](README.md#local-setup). Keep changes focused and
describe the user-visible behavior, validation and remaining limitations.

- Use synthetic accounts and mocked APIs. Do not add live credentials, account
  exports, browser sessions, moderation evidence or database copies.
- Keep product code changes in `worker/`. The retained core and schema files are
  generated by `scripts/extract-core.mjs`; change the relevant adapter or
  extraction input, then regenerate. Do not hand-edit generated files.
- Add a meaningful regression test for changed behavior and run the affected
  tests. Before proposing an integrated code change, run `npm test` and
  `npm run build` with the supported Node version.
- Generate new schema migrations with `npm run db:generate`. Never rewrite an
  applied migration or remove its metadata. Include migration/rollback notes.
- Deployment and public communication require the operator's authorization.
  Local work does not authorize paid APIs, infrastructure spending or live tests.

By contributing, you confirm that you can submit the code under the repository's
ISC license. Third-party contributions must retain their applicable notices.
Report sensitive issues through [SECURITY.md](SECURITY.md).
